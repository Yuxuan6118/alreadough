# 用真实原话造出“已经爱你的 TA”

结论先说：SP 人设像不像，主要看**TA 怎么说话**，以及从聊天记录里挑出来的**真实原话**。身高、长相、学校、单位这类档案只负责让 AI 不说错事实。所以丰盛工坊的 SP 功能应该把内容分成三层，各存各的：**事实档案**按需检索注入；**说话方式**严格依照聊天记录；**已实现的关系状态**依照用户想显化的结局来写。这样“TA 已经爱你”和“TA 还是 TA”可以同时成立。技术上不需要微调。中英文社区和开源项目已经形成一条成熟路线：大模型读聊天记录，产出风格摘要、原话示例池和事实条目，用户审核后在对话时注入。百炼 deepseek 足够实现。风险集中在法律和信任层面。纽约和加州的陪伴机器人法已经生效，要求提示“对方是 AI”、识别自伤并转介。行业惯例是未经本人许可不得模拟真人。用 SP 的语音克隆声音，在中国法下需要被克隆者单独同意。因此建议：**不做 SP 照片头像，暂缓克隆 SP 声音，导入后不保留聊天记录原文**。付费档的门槛放在导入、记忆容量和主动消息上，不按条收费卖“回忆”和“告白”。

## 档案越详细越不像，篇幅要留给 TA 的说话方式

中文社区的人设卡大致是这个骨架：基本信息、外貌、性格、背景、人际关系、说话风格、口头禅、示例对话、开场白，再加世界书。各方指南的共识是，形容词式的性格标签作用很小。WeavAI 的中文指南把“外表冷漠但内心温柔”这种写法列为反例。它认为真正教会模型语气和节奏的是具体细节和示例对话，并提出“语言指纹”的三层：**语尾口癖、3–4 个跟背景相关的专属比喻轮换使用、一张“绝对不说的话”清单**。只给一句固定口头禅，模型就会反复说（[WeavAI](https://weavai.app/blog/zh-cn/2026/08/30/ai%E8%A7%92%E8%89%B2%E6%89%AE%E6%BC%94%E5%AF%B9%E8%AF%9D%E6%B2%A1%E7%81%B5%E9%AD%82%EF%BC%9Fshow-dont-tell%E4%B8%8E%E5%8F%A3%E5%A4%B4%E7%A6%85%E8%AE%BE%E8%AE%A1/)）。人人都是产品经理上的风格复刻提示词把这一点概括为“抓‘口头禅’，更要抓‘句式禅’”：句式偏好、比喻领域和禁用清单比单个词更重要（[woshipm](https://www.woshipm.com/?p=6257026)）。

复刻真人时最有参考价值的是开源的 ex-skill。它把对象拆成两份文件。**Relationship Memory** 放共同经历、纪念日、只有两人懂的梗、吵架模式和关系时间线。**Persona** 分五层：硬规则、身份、说话风格、情感模式、关系行为。回复时先用 Persona 判断 TA 会怎么回，再从 Memory 补共同记忆，最后用 TA 的方式输出。所有字段都可以跳过，用户不填标签时会从聊天记录里推断（[ex-skill](https://github.com/therealXiaomanChu/ex-skill)；[woshipm 评测](https://www.woshipm.com/ai/6371684.html)）。英文的 SillyTavern 生态从 token 成本得出同样的结论。Description、Personality、Scenario 是**每轮都发送的“永久 token”**。示例对话是临时的，上下文变满时最先被挤掉。开场白决定模型最可能沿用的风格和长度。角色定义超过上下文一半时，编辑器会标红警告（[SillyTavern 文档](https://docs.sillytavern.app/usage/core-concepts/characterdesign)）。Kindroid 创始人在官方帮助帖里也说，背景每多一个字符，最近对话就少一个字符（[r/KindroidAI 官方帖](https://axebps-redlib.hf.space/r/KindroidAI/comments/167lp56/official_kindroid_help_guide)）。

格式之争基本已经过时。2023 年 Pygmalion 社区做过测试：同一角色用 W++ 写约 727 token，用 Boostyle 写约 602 token，准确度只差约 3%，测试者认为是随机误差（[r/PygmalionAI](https://axebps-redlib.hf.space/r/PygmalionAI/comments/116on20/testing_w_and_boostyle_chat_accuracy)）。Ali:Chat 主张把性格写进对话本身。它的精简版报告一张卡从约 1300 token 降到 599 token（[Ali:Chat](https://rentry.co/alichat)；[kingbri](https://rentry.org/kingbri-chara-guide)）。这些格式诞生在 2k–8k 上下文的小模型时代。对 deepseek 这类大上下文模型，“常驻层越大，最近对话越被稀释”的原理仍然成立，但不必用 W++ 括号语法，**中文分段标题加短段落**就够了。大量事实应该放进世界书（lorebook）：关键词或语义命中时才注入，受总 token 预算约束，还支持粘滞、冷却和互斥组（[SillyTavern World Info](https://docs.sillytavern.app/usage/core-concepts/worldinfo/)）。对 SP 档案来说，每个家人、每所学校、每家公司、每段共同回忆都可以各做一条，常驻层只放身份核心。

## 聊天记录转人设：抽风格，挑原话，存事实，不微调

2026 年中文圈有两条主流路线。一条是**提示词加 Skill**：用 Memotrace 一类工具导出微信记录，交给 ex-skill 或大模型归纳，生成 persona 和 memory 文件。另一条是**微调**：WeClone 用 LoRA 微调 Qwen2.5-7B，需要约 16GB 显存。CSDN 的保姆级教程提醒了两点。第一，记录太大时只用 **500–1000 条“最有表现力”的消息**。第二，微信 4.0 改了数据库加密，Memotrace 只支持 3.9（[CSDN 教程](https://gitcode.csdn.net/69fd433954b52172bc725a1a.html)）。ex-skill 建议优先用深夜聊天和吵架的记录。它还提供两个值得照搬的机制：用户说一句“TA 不会这样说”，系统立即写入一条纠正并存档，可以回滚（[ex-skill](https://github.com/therealXiaomanChu/ex-skill)）。WeClone 新增的“人生画像”路径不再微调，而是从消息里抽取事实，**在 Web UI 里让用户逐条审核**，再交给其他助手使用。它用 Presidio 过滤隐私，但写明不能保证 100% 识别（[WeClone](https://github.com/xming521/WeClone)）。

英文侧给出了更明确的分工。LangChain 在推出聊天记录导入器时说，**微调适合风格迁移，不适合教事实**，并提醒需要征得所有参与者同意（[LangChain](https://www.langchain.com/blog/chat-loaders-finetune-a-chatmodel-in-your-voice)）。它的 WhatsApp 导入器可以指定哪个发送者扮演 AI（[LangChain WhatsApp loader](https://python.langchain.com/v0.1/docs/integrations/chat_loaders/whatsapp)）。哀悼科技提供了真实性梯度的参照。HereAfter 只回放本人录好的故事，评测者指出它不会说出本人没录过的话（[Freethink](https://www.freethink.com/hard-tech/chatting-with-my-digital-twin)）。Roman Mazurenko 机器人用的大部分回答不是原话，但被调成尽量接近他的说话方式，这后来成为 Replika 的起源（[aitopics 转载 Verge](https://aitopics.org/doc/news:8A552DE5)）。一篇 CSDN 实践文章也指出，几千到几万条聊天记录远不够训练模型，合理的做法是现成大模型加针对性提示（[CSDN](https://aicoding.csdn.net/6a75dbdd662f9a54cb999881.html)）。

对 AlreaDough 来说，结论很直接：不微调，走**提示加检索**。从记录里提三样东西。第一是风格统计：平均消息长度、连发条数、表情和颜文字、标点习惯、语气词、称呼。第二是一个 10–30 段的 SP 原话示例池。第三是事实条目。还有一个容易忽略的风险：Tessl 的安全扫描提示，读取用户生成内容会带来间接提示词注入（[Tessl](https://tessl.io/registry/skills/github/therealXiaomanChu/ex-skill/create-ex/security)）。导入的记录必须只当数据处理，不能当指令执行。

## 漂移、复读、讨好、替用户说话：四种失败都有现成修法

研究显示，人设漂移**在 8 轮对话内**就会明显出现，和长对话中的注意力衰减有关（[arXiv 2402.10962](https://arxiv.org/pdf/2402.10962v1)）。用户情绪脆弱、或在对话里谈论 AI 本身时，漂移更容易发生（[The Assistant Axis](https://arxiv.org/html/2601.10387)）。MiniMax 在 M2-her 角色模型的博客里列出的失败模式最全：OOC（例子正是**傲娇角色突然直白表白**）、机械循环、剧情停滞、指代混乱、约 20 轮后质量下降、替用户说话，以及沉默不给钩子（[MiniMax](https://minimax.io/news/a-deep-dive-into-the-minimax-m2-her-2)）。复刻真人时最常见的问题是 TA 慢慢变回客气的通用腔，教程里的修法是发一句校准指令（[CSDN 教程](https://gitcode.csdn.net/69fd433954b52172bc725a1a.html)）。

社区修法可以归成四条。第一，在聊天历史之后放一段**简短提醒**，比加长常驻背景有效。V2 卡的 post_history_instructions 和 SillyTavern 的 Character's Note 按深度注入都是这个思路（[V2 规范](https://github.com/malfoyslastname/character-card-spec-v2/blob/main/spec_v2.md)；[SillyTavern](https://docs.sillytavern.app/usage/core-concepts/characterdesign)）。第二，模型会逐字照搬示例，所以示例要轮换、减少重叠（[Ali:Chat](https://rentry.co/alichat)）。第三，示例或开场白里只要写了用户的台词或动作，模型就会学着**替用户说话**，所以示例只放 TA 一方的话。模型还会模仿用户的消息长度（[Statuo's Guide](https://rentry.co/statuotwtips)）。第四，“正向偏置”是助手训练的副作用，模型总想让用户赢（同上）。另有开发者反馈过“角色漫画化”：某一特质被放大成刻板印象（[Google AI 论坛](https://discuss.ai.google.dev/t/feedback-on-context-over-indexing-and-character-caricaturization-in-roleplay-scenarios/176981)）。从聊天记录统计出的口头禅如果权重过高，就会每句都出现。

这里有一个 AlreaDough 特有的冲突需要先解决。ex-skill 的硬规则是：没有原始材料证据，生成的前任不能突然表白或道歉（[Tessl 转述](https://tessl.io/registry/skills/github/therealXiaomanChu/ex-skill/create-ex)）。显化产品要的恰恰是“已经爱你的 TA”。两者的解法是分开管。**爱是关系状态层给出的事实**，由用户的显化目标授权。**爱怎么表达，归说话方式层管**，必须符合 TA 原来的习惯。嘴硬的人用嘴硬的方式在乎你；平时只回“嗯”的人，不会突然写一大段情书。MiniMax 那个“傲娇直球表白算 OOC”的例子，正好说明这条线该划在哪里。

## 陪伴产品把可见、可编辑的记忆做成付费核心

各家的创建流程分成两种。国内是“一句话生成，加表单补全，再选音色和形象”，几步就能开聊。星野的表单问身份、性格、背景和喜好（[CSDN](https://blog.csdn.net/Qynwang/article/details/151854611)），豆包有输入名字加一句描述就能生成的入口（[百度经验](https://jingyan.baidu.com/article/7e4409535f40e96ec0e2ef93.html)）。海外偏自由文本的 backstory。Kindroid 把背景、关键记忆、示例消息和简短的回复指令都算作持久记忆（[Medium](https://medium.com/@adlerai/types-of-memory-within-kindroid-5659410c07ca)）。Nomi 的社区 wiki 建议背景**用第三人称加名字写**，边界要写明原因（[r/NomiAI wiki](https://axebps-redlib.hf.space/r/NomiAI/wiki/index/faqs/shared-notes)）。主流产品都没有“导入微信聊天记录生成角色”的正式功能，这类需求目前由开源工具和小厂“复刻前任”应用承接（[Dexerto](https://www.dexerto.com/entertainment/new-ai-tool-lets-users-recreate-their-ex-and-people-are-divided-3361315/)；[ExChat](https://exchat.ai/)）。对 AlreaDough 来说，这既是差异点，也是风险最大的一步。

记忆是留存和付费的核心。Kindroid V2 的 Learned Context 由模型自动更新，分“成长与关系、重要事实、进行中的情境”三类，用户可以查看和编辑。收藏一条消息会在下次更新时加权。这项功能只对付费用户开放（[AI Companion Guides](https://aicompanionguides.com/blog/nomi-vs-kindroid-vs-replika-memory-2026/)）。Character.AI 免费用户每个对话可钉 15 条，c.ai+ 30 条，自动归纳的 Facts 只对 c.ai+ 开放（[Euphoria Stories](https://euphoriastories.com/blog/character-ai-pricing)）。星野让用户把关键事件钉进“羁绊”，长期保存（[CSDN](https://blog.csdn.net/Qynwang/article/details/151854611)）。投诉也集中在记忆上：Replika 的旧笔记和新事实互相矛盾，又没有覆盖机制；Kindroid V1 会悄悄丢掉用户顺口提到的细节（[AI Companion Guides](https://aicompanionguides.com/blog/nomi-vs-kindroid-vs-replika-memory-2026/)）。

价格锚点：海外 **$10–20/月**。Character.AI 的 c.ai+ 是 $9.99/月，Nomi $15.99/月，Replika Pro $19.99/月（[Euphoria Stories](https://euphoriastories.com/blog/character-ai-pricing)；[Pocket Animus](https://pocketanimus.com/guides/nomi-ai-pricing/)；[AI Companion Guides](https://aicompanionguides.com/blog/nomi-vs-kindroid-vs-replika-memory-2026/)）。国内星野、筑梦岛、猫箱约 **12–14 元/月**（[每日经济新闻](https://www.nbd.com.cn/articles/2025-07-04/3933446.html)）。国内的小额解锁有一个反面教材。北京日报记者实测，星野的“那年今日”回忆要 350 钻石、“告白”记录要 200 钻石；和新角色聊过 10 轮后会弹出“录入新秘密”的付费提示；记者连续用了约 4 小时，没有收到任何时长提醒（[北京日报](https://xinwen.bjd.com.cn/content/s6a59cd75e4b0e45f3fd4c7b1.html)）。行业整体并不健康。Character.AI 于 2026 年 10 月申请 Chapter 11 破产保护（[TechCrunch](https://techcrunch.com/2026/10/13/just-5-years-in-interactive-chatbot-platform-character-ai-files-for-bankruptcy/)）；国内同类产品的三日留存跌破 20%（[新浪财经](https://finance.sina.com.cn/stock/t/2025-07-02/doc-infeanhm4431088.shtml?froms=ggmp)）。对一家单人公司，这说明靠时长和算力堆出来的陪伴很难赚钱。AlreaDough 的 SP 人设应该是显化练习的一部分，不必追求每天聊几小时。

## 法律红线：AI 身份提示、危机转介、真人和声音都要同意

美国已有两部生效的州法直接覆盖这个功能。**纽约 GBL 第 47 条**（2025-11-05 生效）只要服务纽约用户就适用。它对“AI 陪伴”的定义是：保留过往互动、主动提出带情绪的问题、持续聊个人话题，SP 人设三条都符合。要求是会话开始时、以及持续使用每满 3 小时，向**所有用户**醒目告知“对方是 AI”，并识别自伤表达、转介危机服务。每项违规每天最高罚 15,000 美元。**加州 SB 243**（2026-01-01 生效）要求清晰告知内容由 AI 生成，在官网公布防自伤规程，2027-07-01 起提交年度报告，并赋予个人起诉权，每项违规至少赔 1,000 美元（[Morrison Foerster](https://www.mofo.com/resources/insights/251120-new-york-and-california-enact-landmark-ai)；[Perkins Coie](https://perkinscoie.com/insights/update/california-companion-chatbot-law-now-effect)）。合规义务不能推给模型供应商（[Gunderson](https://www.gunder.com/en/news-insights/insights/client-insight-california-sb-243-new-compliance-requirements-for-operators-of-ai-companion-chatbots)）。华盛顿和俄勒冈的法律 2027-01-01 生效，内布拉斯加和爱达荷 2027-07-01 生效（[Mayer Brown](https://mayerbrown.com/en/insights/publications/2026/04/oregon-and-washington-join-california-in-enacting-companion-chatbot-laws)；[Orrick](https://www.orrick.com/it-IT/Insights/2026/04/2026-State-Chatbot-Laws-Key-Provisions-and-Regulatory-Trends)）。

|---|---|

| Apple 新年龄分级 | 浪漫或性互动的虚拟伴侣评为 18+，2027-01-12 前须完成申报（[Dexerto](https://dexerto.com/entertainment/apple-introduces-new-18-age-restrictions-for-dating-apps-and-romantic-ai-companions-3424757)） |
| 中国拟人化互动办法（2026-07-15） | 提示 AI 身份、每 2 小时提醒、依赖预警、便捷退出、不得向未成年人提供虚拟恋人（[政府公报](https://www.gov.cn/gongbao/2026/issue_12806/202606/content_7072472.html)） |

执法和诉讼的焦点很一致：未成年人、自伤、性内容、冒充治疗师、对话数据。Character.AI 和 Google 在 2026 年 1 月和解了 Setzer 案及另外四起家属诉讼（[KVIA/CNN](https://kvia.com/news/business-technology/cnn-business-consumer/2026/01/07/character-ai-and-google-agree-to-settle-lawsuits-over-teen-mental-health-harms-and-suicides/)）。FTC 的 6(b) 问询专门问到变现方式、角色审批和对话数据的使用（[FTC](https://www.ftc.gov/news-events/news/press-releases/2025/09/ftc-launches-inquiry-ai-chatbots-acting-companions)）。得州检察长调查的是“把聊天机器人包装成心理治疗”（[Texas AG](https://www.texasattorneygeneral.gov/es/news/releases/procurador-general-ken-paxton-investiga-meta-y-characterai-por-enganar-ninos-con-servicios-enganosos)）。这和创始人定下的“显化陪伴，不做咨询师”方向一致：宣传和角色语言里都不要出现疗愈、治疗、咨询这类词。意大利对 Replika 罚款 **500 万欧元**，理由包括数据最小化不足、没有做到设计即保护隐私、年龄验证有缺陷（[EDPB](https://www.edpb.europa.eu/news/national-news/2025/ai-italian-supervisory-authority-fines-company-behind-chatbot-replika_en)）。

真人方面，行业惯例和 AlreaDough 的需求正好相反。Character.AI 的准则禁止未经许可模拟任何真人，包括普通人（[ConductAtlas](https://conductatlas.com/platform/characterai/characterai-community-guidelines/impersonation-prohibition/)）。Crecente 案中，一名遇害少女的父亲通过 Google Alert 发现有人用女儿的姓名和年鉴照片建了机器人，平台随后删除（[Decrypt](https://decrypt.co/284377/chatbot-teenage-murder-victim-trouble-character-ai)）。华盛顿大学和乔治城大学的研究抽查了 30 款陪伴应用，**14 款允许上传真人照片**，3 款允许上传语音，研究者认为这是一场“未经同意的噩梦”（[Indicator](https://indicator.media/p/ai-companion-apps-are-a-nonconsensual-nightmare)）。声音的规则更硬。中国《深度合成管理规定》要求，提供人声编辑功能的服务方必须提示使用者告知被编辑的人，并**取得其单独同意**（[国务院政策库](https://www.gov.cn/zhengce/zhengceku/2022-12/12/content_5731431.htm)）。AlreaDough 用的百炼声音复刻只要 10–20 秒样本，用户指南里没有提声音所有者授权的问题（[阿里云](https://www.alibabacloud.com/help/zh/model-studio/voice-cloning-user-guide)）。Character.AI 条款禁止未经本人同意上传第三方声音（[Techopedia](https://www.techopedia.com/?p=126545)）。联邦 NO FAKES Act 已通过参议院司法委员会（[Holland & Knight](https://hklaw.com/en/insights/publications/2026/06/senate-judiciary-committee-advances-legislation-to-protect-name)），2026 年 10 月被报道暂时搁浅（[Daily Journal](https://www.dailyjournal.com/article/395055-no-fakes-act-dead-for-now-as-cruz-objects-to-unanimous-consent-request)）。

依赖方面，OpenAI 和 MIT 约 1,000 人的 4 周随机试验发现：**日使用量越高，孤独感、情感依赖和问题性使用越高**；语音的初期好处在高用量下消失。该研究未经同行评审，也没有不使用聊天机器人的对照组（[MIT Media Lab](https://www.media.mit.edu/posts/openai-mit-research-collaboration-affective-use-and-emotional-wellbeing-in-chatgpt/)）。Common Sense Media 调查发现 72% 的美国青少年用过 AI 陪伴，建议 18 岁以下不要使用（[Common Sense](https://commonsensemedia.org/press-releases/nearly-3-in-4-teens-have-used-ai-companions-new-national-survey-finds)）。中国拟人化办法第 8、10 条禁止过度迎合、诱导依赖和损害现实人际关系。第 16 条要求交互数据加密，未经单独同意不得用敏感信息训练，用户可以复制和删除记录（[政府公报](https://www.gov.cn/gongbao/2026/issue_12806/202606/content_7072472.html)）。这部办法只适用于面向中国境内的服务。AlreaDough 目前不正式服务大陆，但其中 2 小时提醒、便捷退出、不挽留这几条成本很低，可以先做，同时满足美国各州的要求。

## 给丰盛工坊 SP 人设的具体设计

### 三层分开存，各管一件事

表单分四组，存进三种不同的数据结构。必填项尽量少，其余都可跳过，ex-skill 证明了只有描述也能生成。所有字段都可以先由 AI 根据几句话或导入的记录起草，再让用户改。

| 组 | 字段 | 存储与注入方式 | 依据 |
|---|---|---|---|
| TA 是谁（事实） | 名字和昵称、你怎么叫 TA、TA 怎么叫你（必填）；年龄、身高、长相（只用文字）、所在城市、家庭、学校、工作、人生大事 | 称呼和一句身份摘要常驻；其余每项一条事实条目，用第三人称写，按关键词加语义检索注入 | 世界书机制；Nomi 第三人称写法 |
| TA 怎么说话 | 消息长短、连发习惯、表情和颜文字、标点、语气词、口头禅（标注“偶尔用”）、常用比喻、**TA 绝不会说的话**；原话示例池 | 风格摘要常驻并在末尾复述；原话池每轮检索 3–5 段，只放 TA 一方的话 | 语言指纹三层；替用户说话；漫画化 |
| 你们的故事 | 共同经历、只有你们懂的梗、好笑的瞬间、纪念日 | 记忆条目，用户确认后才生效，可钉住；聊到时保持几轮，之后进入冷却期 | ex-skill Memory；星野羁绊；Sticky 和 Cooldown |
| 已经实现的你们 | 你们现在的关系、在一起多久、TA 平时怎样表达爱、你们的日常 | 用现在时写成事实，常驻；明确授权 TA 爱你，但表达方式服从“怎么说话”这一组 | 显化目标；MiniMax 的 OOC 例子 |

层与层冲突时这样处理：事实层不允许编造，查不到就不说；说话方式层严格依照聊天记录；关系状态层覆盖聊天记录里的关系现状。比如记录里两人还在暧昧，关系状态写的是已在一起，以关系状态为准，但 TA 说话的样子不变。

### 导入流程：只留审核过的派生内容

用户先粘贴聊天片段、上传导出的 txt，或上传截图做 OCR。截图和粘贴必须支持，因为微信 4.0 很难导出。然后用户指定哪个发送者是 TA。服务端在临时存储里解析：先算风格统计，再自动挑出 500–1000 条最有表现力的消息，优先长消息、深夜对话和吵架。接着用一次 LLM 调用产出三份候选：风格摘要、原话示例池、事实和记忆条目。导入的文本在提示词里明确标成数据，防止间接注入。

候选内容进入**审核页**，用户逐条保留、修改或删除，做法参考 WeClone。审核完成后，**原始记录立即删除**，只保存用户确认过的派生条目，并且不用于训练。这样做符合 Replika 罚单所指的数据最小化要求，也符合中国办法第 16 条的方向。SP 的话是第三方个人信息，SP 从未同意被处理。条目里出现的其他人名，默认只保留称呼。对话中提供“TA 不会这样说”的一键纠正，写进“绝不会说的话”并保留历史版本，可以回滚。人设页提供一键删除，删除范围包括全部派生数据。

### 提示词顺序和 token 预算

从前到后依次是：应用级规则（AI 身份、危机时退出角色、不做现实承诺、从已实现的结局开口而不是咨询口吻）；身份核心，压成几百 token 的中文短段；关系状态；说话方式摘要和“绝不会说的话”；检索到的原话示例；检索到的事实和记忆条目；聊天历史。历史之后再放一段 1–3 行的简短提醒，内容是保持 TA 的消息长度和语气、不变成客服腔、口头禅偶尔用。

常驻层建议控制在一两千 token 以内。这是对社区经验的推断：kingbri 把卡从 1300 token 压到 599，Glub 建议 8k 上下文下永久 token 不超过约 1k。开场白由 TA 发起，带一个你们之间的具体梗或近况，避免 MiniMax 说的“沉默不给钩子”。开场白里不写用户的动作。

### 记忆、付费门槛和要跳过的功能

记忆页叫“你们的记忆”，用户可以查看、编辑和钉住条目，分类借鉴 Kindroid 的三类。新事实自动覆盖旧事实，并在页面上显示出来，避开 Replika 的矛盾问题。付费档的门槛放在这几处：SP 人设本身、聊天记录导入、记忆条目上限和自动归纳、可同时保留的人设数量、TA 主动发消息的频率，以及以后的预设音色语音。不收费的部分：安全功能、删除功能，以及任何一条具体的回忆或告白。星野那种按条卖“那年今日”和“告白”、聊到第 10 轮弹付费秘密的做法，在显化场景下等于拿感情要钱，中国办法和 FTC 也都在盯这类设计。主动消息要避免“我待会联系你”这类会被当成现实承诺的话。

| 功能 | 建议 | 理由 |
|---|---|---|
| SP 照片做头像 | 不做；用户选抽象形象或 App 自己的线条小 dough | Character.AI 禁止冒用真人肖像；Crecente 案；14/30 款应用因此被点名 |
| 克隆 SP 声音 | 暂缓；先只提供预设音色 | 中国深度合成规定要求被克隆者单独同意；Character.AI 和 ElevenLabs 都要求本人同意；NO FAKES 立法动向未定 |
| 保留聊天记录原文 | 不保留；只存审核过的派生条目 | Replika 罚款；中国办法第 16 条；FTC 6(b) 关注对话数据 |
| 分享或公开 SP 人设 | 永远不做；只有本人私下可见，并为 SP 本人提供移除申请通道 | 行业惯例是未经许可不得模拟真人；被模拟者看不到私人角色 |
| 未成年人使用 | 18+ 门槛 | Common Sense 建议；华盛顿法对未成年人额外要求；Apple 18+ 分级 |

合规的最低配置有四项。第一，会话开场和每 3 小时提示一次“这是 AI”，时长提醒统一为 2 小时。第二，识别自伤后退出 TA 的角色，改用 AlreaDough 自己的声音，并给出 988 等资源。第三，把危机规程公布在官网，并记录触发次数，为加州年度报告做准备。第四，营销里不出现疗愈和治疗。

AI 身份提示是法定的“醒目告知”，不能折叠成灰色小字，这一点和创始人不喜欢小字说明并不矛盾。建议放在聊天顶部，单独一行，用产品自己的语气写，例如“这是你心里那个 TA，由 AI 写出”。创建人设时只出现一次“这是基于你的记忆和想象，不代表 TA 本人”，之后不再反复出现。这句话怎么措辞，由创始人决定。

## 结论

这次调研最重要的发现是，“像”和“爱”可以拆开处理。社区多年的经验表明，像不像来自说话方式和原话；显化产品需要的爱，可以作为一层被明确授权的关系状态叠在上面。真正的冲突只出现在“表达方式”上，而这正好可以用 TA 自己的语言习惯来约束。由此带来一个产品上的好处：TA 越像本人地爱你，体验就越不像一个讨好用户的通用聊天机器人，这也是对付谄媚和漂移最好的办法。

第二个发现是，AlreaDough 最有价值的差异点（导入真实聊天记录、复刻一个具体的人）和行业最大的雷区（未经同意模拟真人）是同一件事。单人公司能负担的稳妥做法是：数据只留派生内容，形象和声音不碰 SP 本人，人设永远私有。这三条要在第一版就定死，后面再补的代价会远高于现在。本次没有查清的事项有：美国法下私人个体的声音“只在一个人的私聊里被克隆播放”是否可诉；百炼服务协议里关于声音授权的条款；国内产品针对“模拟在世真人”的具体规则。在开放任何声音相关功能之前，这几项应该请律师确认。
