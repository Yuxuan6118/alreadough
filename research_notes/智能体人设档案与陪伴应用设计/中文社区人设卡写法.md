## 1. 中文创作者的人设卡用哪些字段？哪些字段最影响“像不像”？

### Takeaway
中文社区常见的字段骨架是：基本信息 → 外貌 → 性格 → 背景经历 → 人际关系 / 与用户的关系 → 说话风格 / 口头禅 → 示例对话 → 开场白 →（世界书 / 记忆）。各方指南的共识是：**“像不像”主要取决于说话风格和示例对话，形容词式的性格标签作用很小**。复刻真人时，ex-skill 把“共同记忆”单独拆成一个文件，与 Persona 分开管理。

### Cited Findings
- 网上流传的人设卡样例（“小樱”式）包含：弱点、语言特色（常用语气词、颜文字）、日常模式（早晨、开心、害羞、撒娇、困惑等情境下各给几句示例台词）、兴趣爱好、“小秘密”。另一种“阿杰”式写法是：身份与目标 → 说话特点 → 几组极短的问答当示例对话，适合话少、风格鲜明的角色。[搜索摘要，来源是 HF 数据集预览页，可信度低] — [HF dataset viewer](https://huggingface.co/datasets/chimaobi03/DSNet_Loss/viewer/default/train)
- 机核《角色构建方法论：解构角色的16个切面》（猫翼子，2023-05-25）列出 16 个维度：基本信息、性格、内心剖析、外貌、童年经历、环境影响、目标与遗憾、社会关系、情绪状态、恋爱互动、恋爱冲突、特殊伙伴，以及几类物品。作者原话是“并非每一个角色都需要这么多方面的设定”。这篇写给人类创作者，没有谈 AI 卡。[直读] — [GCORES](https://www.gcores.com/articles/166079)
- WeavAI 中文博客（2026-08-30）认为“外表冷漠但内心温柔”这类只有形容词的性格栏是反例：AI 用不好“友善”“复杂”这类空泛形容词，真正教会它语气、节奏、情绪逻辑的是具体细节和示例对话。[直读] — [WeavAI: Show, Don't Tell 与口头禅设计](https://weavai.app/blog/zh-cn/2026/08/30/ai%E8%A7%92%E8%89%B2%E6%89%AE%E6%BC%94%E5%AF%B9%E8%AF%9D%E6%B2%A1%E7%81%B5%E9%AD%82%EF%BC%9Fshow-dont-tell%E4%B8%8E%E5%8F%A3%E5%A4%B4%E7%A6%85%E8%AE%BE%E8%AE%A1/)
- 同一篇文章提出“语言指纹”三层：①语尾口癖（固定句尾词，或紧张时先干笑一声）；②专属比喻库（3–4 个跟角色背景相关的比喻轮换使用，例如厨师用“火候”“调味”）；③“绝对不说的话”清单，作者称之为“负空间”。它的逻辑是：只给一句固定口头禅会被反复说（“跳针”），三层叠加后才有变化。[直读] — [WeavAI](https://weavai.app/blog/zh-cn/2026/08/30/ai%E8%A7%92%E8%89%B2%E6%89%AE%E6%BC%94%E5%AF%B9%E8%AF%9D%E6%B2%A1%E7%81%B5%E9%AD%82%EF%BC%9Fshow-dont-tell%E4%B8%8E%E5%8F%A3%E5%A4%B4%E7%A6%85%E8%AE%BE%E8%AE%A1/)
- 示例对话的建议：覆盖几种明显不同的场景（打招呼、意见不合、告别），不要写十句意思相同的台词；用标点、句长、用词区分声音（短促句 vs 带省略号的拖长句）。[直读] — [WeavAI](https://weavai.app/blog/zh-cn/2026/08/30/ai%E8%A7%92%E8%89%B2%E6%89%AE%E6%BC%94%E5%AF%B9%E8%AF%9D%E6%B2%A1%E7%81%B5%E9%AD%82%EF%BC%9Fshow-dont-tell%E4%B8%8E%E5%8F%A3%E5%A4%B4%E7%A6%85%E8%AE%BE%E8%AE%A1/)
- “抖知书”在人人都是产品经理（2025-08-18）上的风格复刻提示词，把“语言风格”拆成：句式偏好（反问、短句）、常用比喻领域（比喻库）、禁用清单（套话、“首先其次最后”、结尾总结）。原话是“抓‘口头禅’，更要抓‘句式禅’”。作者也承认这样出来的输出“显得很‘硬’”。[直读] — [woshipm 6257026](https://www.woshipm.com/?p=6257026)
- ex-skill（前任.skill）把复刻对象拆成两部分：**Part A Relationship Memory**（共同经历、纪念日、只有两人懂的梗、吵架模式、甜蜜时刻、关系时间线 → memory.md）和 **Part B Persona**（五层：硬规则 → 身份 → 说话风格 → 情感模式 → 关系行为 → persona.md）。回复流程是：收到消息 → Persona 判断 ta 会怎么回 → 从 Memory 补充共同记忆 → 用 ta 的方式输出。[直读 GitHub README] — [therealXiaomanChu/ex-skill](https://github.com/therealXiaomanChu/ex-skill)
- ex-skill 的标签体系：依恋类型（安全 / 焦虑 / 回避 / 混乱）、爱的语言（肯定的话语、精心时刻、礼物、服务、身体接触）、性格标签（话痨、闷骚、嘴硬心软、冷暴力、粘人、“深夜发语音”等）、12 星座、16 种 MBTI。README 写明“所有字段均可跳过，仅凭描述也能生成”。示例输入是：初恋、在一起三年、大学时期、ENFP、双子座、话多、深夜发语音、分手后还点赞。[直读] — [ex-skill README](https://github.com/therealXiaomanChu/ex-skill)
- 人人都是产品经理一篇评测（AI星球，2026-04-07）的转述：Persona 五层从硬规则到关系行为；Memories 包含时间线、习惯、情感模式；Tags 包含恋爱人格、冲突模式、依恋类型、爱的表达方式；用户不填标签时系统会从聊天记录里推断。[直读] — [woshipm 6371684](https://www.woshipm.com/ai/6371684.html)

### Inferences
- 对 AlreaDough 来说，用户填的身高、长相、年龄、家庭、学校、单位这些“档案”，主要作用是让 AI 不说错事实，对“像不像”帮助不大。“像”主要来自三样东西：①从聊天记录里提出来的说话风格（句式、语气词、表情、回复长短）；②几段真实对话当示例；③共同记忆里的具体梗。表单可以按这个比重安排篇幅。
- “绝对不说的话 / 负空间”和 ex-skill 的“硬规则”说的是同一件事：一张“ta 不会说 / 不会做”的清单。这个字段最便宜，效果也最直接。

### Gaps
- 没有拿到小红书或知乎原帖里的人设卡模板，上面的字段骨架是根据多处二手材料归纳的。
- 没有找到对“哪个字段贡献多少”做过对照实验的中文资料，现有说法都是经验之谈。

## 2. 小红书 / 知乎 / B站怎么教“用聊天记录复刻前任 / 做 AI 分身”？用哪些工具、哪些提示词步骤？

### Takeaway
2026 年中文圈的主流做法分两条路。①**提示词 + Skill 路线**（门槛低，火得多）：先用 Memotrace / 留痕 / PyWxDump 导出微信记录，再把 ex-skill 这类 Claude Code skill 或豆包、Kimi 之类的大模型拿来读记录、归纳风格，生成 persona.md 和 memory.md。②**微调路线**：WeClone，用 LoRA 微调 Qwen2.5-7B，需要约 16GB 显存。普遍的提醒有：精选 500–1000 条最有代表性的消息，比整份记录塞进去效果好；深夜长聊和吵架最能体现一个人；即使复刻出来，也总会在某个时刻露馅。

### Cited Findings
- CSDN / AtomGit 保姆级教程（2026-05-08）给出的流程：Windows 装微信 3.9.12（作者说 4.0 改了数据库加密，Memotrace 用不了）→ 用 Memotrace 找库、取密钥、解密 → 选“AI 对话专用 TXT”格式导出某个联系人 → 在 Claude Code 项目里把 ex-skill 克隆到 `.claude/skills/create-ex` → 输入 `/create-ex` → 填基本信息并给出 TXT 路径。[直读] — [CSDN 教程](https://gitcode.csdn.net/69fd433954b52172bc725a1a.html)
- 同一教程的避坑部分：文件太大或 token 溢出时，只用 500–1000 条“最有表现力”的消息；人设漂移、回复变成客气的通用腔时，再发一句“保持 ta 的人设继续”之类的校准指令。[直读] — [CSDN 教程](https://gitcode.csdn.net/69fd433954b52172bc725a1a.html)
- ex-skill 支持的数据源：微信导出（WeChatMsg / 留痕 / PyWxDump，README 认为信息最丰富）、QQ 的 txt/mht（适合学生时代的感情）、朋友圈和微博截图（用来提取公开形象）、带 EXIF 的照片（建时间线和地点）、口述或粘贴的文字（用户的主观记忆）。README 建议优先用深夜聊天和吵架的记录。[直读] — [ex-skill README](https://github.com/therealXiaomanChu/ex-skill)
- ex-skill 的进化机制：可以追加新的聊天或照片做增量合并；用户说一句 “ta不会这样说”，系统就写入一条纠正并立刻生效；每次更新都存档，可以用 `/ex-rollback` 回滚。[直读] — [ex-skill README](https://github.com/therealXiaomanChu/ex-skill)
- 第三方转述的 ex-skill SKILL.md 硬规则：不让生成的前任说出现实中 ta 绝不会说的话（例如突然表白、道歉），除非原始材料里有证据；用户表现出不健康的执念时，温和提醒并建议寻求专业帮助。[搜索摘要] — [tessl registry](https://tessl.io/registry/skills/github/therealXiaomanChu/ex-skill/create-ex)
- 同名仓库有好几个（therealXiaomanChu / perkfly / titanwings / w1ndys），无法确认哪个是原版。Tessl 的安全扫描提示一项低风险：读取用户生成内容带来的间接提示词注入。[搜索摘要] — [tessl security](https://tessl.io/registry/skills/github/therealXiaomanChu/ex-skill/create-ex/security)、[skillsllm](https://skillsllm.com/skill/ex-skill)
- ex-skill README 的定位是“不是为了挽回，是为了记住”。评测作者认为它也可以用来保存已故亲人的说话方式。数据质量方面：零碎的聊天效果差，长期、真实的对话效果好。[直读] — [woshipm 6371684](https://www.woshipm.com/ai/6371684.html)
- WeClone（GitHub，最新更新标注为 26/11/03）现在有两条路径。①“人生画像” `build-profile`：从消息里抽取、整理、总结，在 Web UI 里逐条审核事实，再通过 MCP 接给其他助手，或把导出的文字贴进助手的记忆；画像和抽取提示词都是中文。②微调 `make-dataset → train-sft`：默认 Qwen2.5-7B-Instruct + LoRA，约 16GB 显存。用 Microsoft Presidio 加自定义屏蔽词过滤隐私，但写明不能保证 100% 识别。当前只直接支持 Telegram JSON，其他来源要先转成通用 CSV。[直读] — [xming521/WeClone](https://github.com/xming521/WeClone)
- 较早的报道说 WeClone 默认用 ChatGLM3-6B，会把微信记录自动转成 QA 问答对，还有语音克隆子项目 WeClone-audio。这和现在的 README 不一致，以 README 为准。[搜索摘要] — [aibase](https://www.aibase.com/zh/news/17093)、[阿里云开发者 WeClone & Second Me](https://developer.aliyun.com/article/1663072)、[掘金](https://juejin.cn/post/7563499835918991398)
- 一篇 CSDN 实践文章指出：聊天记录一般只有几千到几万条，远不够从零训练模型，更合理的是现成大模型加针对性提示。[搜索摘要] — [aicoding.csdn.net](https://aicoding.csdn.net/6a75dbdd662f9a54cb999881.html)
- 风格提取的通用步骤（多篇文章的共识）：直接说“模仿我”效果很差，要先给样本，让 AI 分析用词、句式、语气，再按分析结果生成；只学到口头禅这种表层，碰到没见过的情境就会露馅，还要归纳思维方式。[直读 + 搜索摘要] — [woshipm 6257026](https://www.woshipm.com/?p=6257026)、[woshipm 6223973](https://www.woshipm.com/?p=6223973)
- 媒体报道里的用户反馈：“确实像她，但终究不是她”；复刻总会在某个瞬间露出马脚。[搜索摘要] — [文学城 2026-07-18](https://www.wenxuecity.com/news/2026/07/18/126712601.html)、[凤凰网](https://news.ifeng.com/c/8sWcH3QJVSZ)、[机核 186881](https://www.gcores.com/articles/186881)

### Inferences
- AlreaDough 不需要做微调。业内事实上的做法是“LLM 读记录 → 生成结构化 persona + memory 文件 → 对话时注入”，这和 ex-skill、WeClone 画像路径一致，用百炼 deepseek 就能实现。
- 很值得照搬的两个机制：①让用户审核从记录里抽出的事实（WeClone 的 Web UI 审核）；②一键纠正“ta 不会这样说”，写入硬规则并保留版本（ex-skill）。
- 导入时自动挑出“最有表现力”的 500–1000 条（深夜聊天、吵架、长消息），既省 token 又提高相似度。
- 微信 4.0 导出困难是实际的门槛（教程说 Memotrace 只支持 3.9）。App 里最好同时支持“粘贴片段 / 截图 OCR”这种低门槛入口。

### Gaps
- 没有直接读到小红书笔记或 B站视频（B站页被验证码挡住），也没有找到“豆包 / Kimi 读聊天记录生成人设”的具体提示词原文。
- ex-skill 是怎么量化口头禅、语气词、emoji、回复长度的，README 没写，需要读 `prompts/persona_analyzer` 等源码才知道。

## 3. 星野 / 猫箱 / 筑梦岛 / 豆包智能体 / 腾讯元器 / 扣子 的创建表单问什么、给哪些技巧？

### Inferences
- 星野、猫箱、筑梦岛的表单大致都是“形象 + 声音 + 人设文本 + 开场白 + 是否公开”这一套。复刻真人的场景里，开场白最好由 ta 发起，并带一个两人之间的具体梗或近况（参考豆包“引导用户先开口”的思路，以及 MiniMax 说的“沉默不给钩子”这个反面）。

## 4. SillyTavern / 酒馆中文社区怎么写角色卡和世界书？token 预算和格式（W++ / 纯文本 / JSON）怎么建议？

### Takeaway
酒馆的思路是：**常驻部分（描述、性格）尽量短，世界书按关键词触发，示例对话写少而精**。格式上，当前社区倾向“分段标签 + 自然语言段落”的混合写法；W++ 更省 token，但写出来生硬，旧模型可能读不懂。没有找到可靠的中文实测 token 对比。

### Cited Findings
- SillyTavern 官方文档的机制（经 WeavAI 转述）：描述和性格字段是每轮都发送的“永久 Token”；对话变长时，示例对话最先被挤出上下文。所以设定要精简，把篇幅留给少数几段高质量的示例对话。[直读] — [WeavAI](https://weavai.app/blog/zh-cn/2026/08/30/ai%E8%A7%92%E8%89%B2%E6%89%AE%E6%BC%94%E5%AF%B9%E8%AF%9D%E6%B2%A1%E7%81%B5%E9%AD%82%EF%BC%9Fshow-dont-tell%E4%B8%8E%E5%8F%A3%E5%A4%B4%E7%A6%85%E8%AE%BE%E8%AE%A1/)
- 第一条消息（开场白）最关键：充满动作和感官细节的开场白，往往决定后面回复的风格。[直读] — [WeavAI](https://weavai.app/blog/zh-cn/2026/08/30/ai%E8%A7%92%E8%89%B2%E6%89%AE%E6%BC%94%E5%AF%B9%E8%AF%9D%E6%B2%A1%E7%81%B5%E9%AD%82%EF%BC%9Fshow-dont-tell%E4%B8%8E%E5%8F%A3%E5%A4%B4%E7%A6%85%E8%AE%BE%E8%AE%A1/)
- 世界书（World Info / Lorebook）：只有关键词被触发时，对应条目才插入提示词，不需要让所有设定常驻；中文社区说的“世界书”就是 lorebook。还有人把配角的长篇细节放进世界书，角色卡里只留一句摘要。[搜索摘要] — [sillycard lorebook 指南](https://sillycard-web.pages.dev/blog/silly-tavern-lorebook-world-info-guide)、[mokimoko templates](https://mokimoko.github.io/pages/guides/character-templates.html)
- 卡片版本：V2 增加了备用开场白、系统提示词覆盖、post-history 指令、标签、内嵌世界书；V3 增加了资源和更强的世界书。[搜索摘要] — [tech-insider SillyTavern Character Cards 2026](https://tech-insider.org/?p=53028)
- 格式比较：W++ 用括号分组属性，省 token，也能减少华丽文风对模型的干扰，但较小或较旧的模型可能把括号当成代码；纯文本 / 自然语言更能表达复杂情绪，但 token 多，还容易出现“trait bleeding”；作者认为效果最好的通常是混合写法。另有指南主张用连贯的段落，不要堆标签，并且行为要能追溯到成长背景。[搜索摘要，英文来源] — [oreateai](https://discover.oreateai.com/discover/build-high-performance-sillytavern-character-cards-for-immersive-roleplay)、[tech-insider](https://tech-insider.org/?p=53028)
- 社区经验：上下文窗口变大以后，token 数没以前那么要紧；有作者把常驻内容控制在几百到两千 token，但这属于个人偏好。[搜索摘要] — [rentry NG_Context2RAGs](https://rentry.co/NG_Context2RAGs)
- 中文资料入口：B站专栏《SillyTavern教程（四）角色卡创建》（2025-02，抓取时被验证码拦截），建议先填性格摘要、角色描述、开场白三项，开场白用 {{user}} 指代用户、写成场景化；非官方中文文档仓库 yuanhuakk/sillytavern-docs-zh。[搜索摘要] — [B站 opus](https://www.bilibili.com/opus/1032263314809290761)、[sillytavern-docs-zh](https://context7.com/yuanhuakk/sillytavern-docs-zh)

### Inferences
- 套到 AlreaDough 的 SP 档案上：常驻 system prompt 只放硬规则、身份摘要、说话风格和几段示例对话；学校、单位、家庭、具体往事、梗这类内容做成“世界书 / 记忆条目”，按关键词或检索注入。这样档案再长也不会把 token 撑爆。
- 不要直接把 W++ 喂给 deepseek。用中文分段标题加短段落的混合格式就够了。

### Gaps

## 5. 常见失败模式（OOC、人设崩、太讨好、复读、AI味）和修法

### Takeaway
各方报告的高频问题是：变回客气的通用腔（复刻真人时最常见）、复读或跳针、“感到很开心 / 露出温柔的笑容”这类套话、说出 ta 绝不会说的话（尤其是突然表白或道歉）、长对话以后忘事或指代混乱、替用户说话。修法集中在：硬规则或负空间清单、示例对话、Show don't tell、校准指令、纠正写回人设、精选语料。

### Cited Findings
- 人设漂移、回到通用礼貌腔：发校准指令，要求保持 ta 的人设。[直读] — [CSDN 教程](https://gitcode.csdn.net/69fd433954b52172bc725a1a.html)
- 说出 ta 不可能说的话：用 Layer 0 硬规则禁止，没有原始材料证据就不突然表白、不道歉。[搜索摘要] — [tessl](https://tessl.io/registry/skills/github/therealXiaomanChu/ex-skill/create-ex)；用户纠正“ta不会这样说”会立即写回人设。[直读] — [ex-skill](https://github.com/therealXiaomanChu/ex-skill)
- 复读、跳针：只有一句固定口头禅就会被反复说，改用“语尾口癖 + 比喻库轮换 + 负空间”三层；五感不要句句都写，每次选 1–2 个重点轮流用。[直读] — [WeavAI](https://weavai.app/blog/zh-cn/2026/08/30/ai%E8%A7%92%E8%89%B2%E6%89%AE%E6%BC%94%E5%AF%B9%E8%AF%9D%E6%B2%A1%E7%81%B5%E9%AD%82%EF%BC%9Fshow-dont-tell%E4%B8%8E%E5%8F%A3%E5%A4%B4%E7%A6%85%E8%AE%BE%E8%AE%A1/)；MiniMax 也说模型天然倾向机械循环和重复句式。[直读] — [MiniMax](https://minimax.io/news/a-deep-dive-into-the-minimax-m2-her-2)
- AI味套话：用动作、感官细节、沉默来代替直接宣告情绪（Show, don't tell）。[直读] — [WeavAI](https://weavai.app/blog/zh-cn/2026/08/30/ai%E8%A7%92%E8%89%B2%E6%89%AE%E6%BC%94%E5%AF%B9%E8%AF%9D%E6%B2%A1%E7%81%B5%E9%AD%82%EF%BC%9Fshow-dont-tell%E4%B8%8E%E5%8F%A3%E5%A4%B4%E7%A6%85%E8%AE%BE%E8%AE%A1/)；禁止“首先、其次、最后”和结尾总结。[直读] — [woshipm 6257026](https://www.woshipm.com/?p=6257026)
- OOC 的三件套：把行为准则写进卡里、正确使用 OOC 指令、配合 lorebook 和记忆系统。还有人建议开头就放结构化设定，并声明它是最高优先级。[搜索摘要] — [WeavAI OOC 3 methods](https://weavai.app/blog/en/2026/08/31/how-to-fix-ai-roleplay-ooc-3-proven-methods/)
- 长对话失忆、指代混乱，大约 20 轮后质量下降；替用户说话；沉默不给钩子；剧情停滞。[直读] — [MiniMax](https://minimax.io/news/a-deep-dive-into-the-minimax-m2-her-2)
- 只学到表层（口头禅、小动作），新情境里露馅：要同时归纳思维方式和价值判断。[直读 + 搜索摘要] — [woshipm 6257026](https://www.woshipm.com/?p=6257026)
- 语料零碎导致不像：用长期、真实的对话，优先深夜聊天和吵架。[直读] — [woshipm 6371684](https://www.woshipm.com/ai/6371684.html)、[ex-skill](https://github.com/therealXiaomanChu/ex-skill)
- 伦理和情绪风险：可能沉溺过去、产生执念；ex-skill 要求温和提醒并建议寻求专业帮助，并提醒用户 skill 只代表“你记忆中的 ta”；WeClone 提醒聊天记录里有他人消息，涉及同意和当地法律。[直读] — [ex-skill](https://github.com/therealXiaomanChu/ex-skill)、[WeClone](https://github.com/xming521/WeClone)

### Inferences
- 显化（manifestation）App 和“怀念前任”是反方向：用户希望 SP 是**已经爱上自己的版本**。这和 ex-skill 的“没有证据就不表白、不道歉”硬规则正面冲突。设计上需要区分两类内容：说话方式要严格忠于聊天记录（像不像靠这个）；关系状态和情感内容按用户想显化的“已实现”状态来写。另外要防止“太讨好”：MiniMax 举的傲娇突然直球表白属于 OOC，也就是说，一个人表达爱的方式本身要符合 ta 原来的风格。
- “ta 只代表你记忆中的 ta”这类提醒，和创始人定下的“显化陪伴、不做咨询师”的语气是有张力的，具体怎么措辞要由创始人决定。

### Gaps
- 没有找到中文社区针对“太讨好 / 谄媚”的专门修法文章，MiniMax 的博客也没有直接讨论谄媚问题。
